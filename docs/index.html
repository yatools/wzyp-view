LangGraph AI 分析

问一句，
Agent 自己写 SQL 查给你

内置 planner ⇄ tools 双节点 LangGraph Agent：绑定只读 SQL 工具，自动拆解问题、执行查询、 流式输出 markdown 表格与结论，还会附上 3 条可直接点选的追问建议。 在商品页点「AI 解读」，当前查询结果一键带入对话。

针对本地小模型实测打磨的防幻觉五件套：schema 动态行数、SQL 报错自动回灌纠正、 工具结果竖线表格直喂、系统提示每轮重注入、追问轮防复读。

✓ 流式 markdown 渲染 ✓ 自动追问建议 ✓ 多会话管理 ✓ 长期记忆 + 滑动窗口压缩
店铺 / 商品多维查询

筛选构建器 + 详情抽屉，

✓ 字段筛选构建器 ✓ 商品详情抽屉 ✓ 抓取状态徽章 ✓ 卡密 / 权益 / 资源 / 文章分色标签

架构

小而完整的 Agent 链路

单文件 FastAPI 服务 + 原生 JS SPA，无重型前端框架；Agent 只有 planner 与 tools 两个节点，链路短、好排查。

🧠planner

LLM + bind_tools：拆解问题、决定调用哪个只读 SQL 工具，组织流式回答与追问建议。

⇄

🔧tools

只读 SQL + schema 自省：结果渲染为竖线表格直喂，杜绝 JSON 转录失真。

→

🗄️SQLite

两个平台独立保存采集快照，查询仅允许读取业务表，SSE 推流到前端。

防表名幻觉 — 「仅有 3 张表」显式声明 + few-shot 示例 SQL
报错自愈 — Unknown table/column 自动回灌，引导核对 schema 重写
无数据不硬编 — data_schema 后强提示「无数据行」
记忆体系 — 长期记忆持久化 + 24 条滑动窗口 + 历史摘要压缩
快速开始

两条路，五分钟跑起来

A本地运行（uv）推荐
# 1. 建环境、装依赖（Python ≥ 3.11，需 curl）
uv venv --python 3.13
uv pip install -r requirements.txt

# 2. 启动后选择平台并采集
python run.py   # → http://127.0.0.1:8770
BDocker Compose一条命令
git clone https://github.com/Samge0/wzyp-view.git
cd wzyp-view
docker compose up -d --build

# → http://localhost:8770

# 配置同样走页面设置，持久化在 ./data volume
# 容器内连宿主机 LLM：
#   http://host.docker.internal:<port>/v1

打开页面后选择「链动小铺」或「16688 交易平台」采集商品；如需 AI 分析，再到设置页配置 LLM。历史备份仅提供店铺入口，商品和价格须重新采集成功后才展示。
